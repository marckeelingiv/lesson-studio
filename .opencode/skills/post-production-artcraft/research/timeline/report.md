## Agent discovery and safe addressing

Use MCP `command_list {filter, enabled_only}` → `command_run {id, params}`; `command_batch {steps:[{id,params}],stop_on_error:true}` is ordered execution, **not evidence of transaction/rollback**. Raw control equivalents: `engine.commands`, `engine.execute {"command":ID,"params":{...}}`. CLI discovery: `filmcraft-cli describe ID`. These are proposed usage, not commands run in this research.

Read `project_inspect` / `sequence_inspect` first. An imported **item** ID identifies project media; a **clip** ID identifies an instance on the timeline; neither is a track, stream index or layer index. Keep source provenance as item/path + stream + source range, not just current clip ID (razor/overwrite can create new instances). Prefer explicit target IDs over selection; discovery's `enabled` reflects current selection even when explicit named targets can bypass that selection condition.

`effects.list {"kind":"Video","detail":true}` (or `"Audio"`) publishes definitions, parameter IDs, kinds/defaults, ranges, units, choices and animatability. Do not guess UI labels or reuse DSP-internal schemas as engine payloads. `effects.apply {"clips":[CLIP],"effect":"ID"}` returns applied instance addresses; use the returned index, especially when an effect occurs more than once. A string effect ID selects the first matching instance.

Evidence: `docs__agents.md:74-120,206-234`; `crates__engine__src__commands.rs:3693-3752,4190-4202`. Important inspection limits at `commands.rs:5268-5302`: effect values are debug strings and keyframes are **counts**, not full editable curves; no `audio_stream`, `source_channels`, or caption-track list is emitted there. Save a scratch `.fcproj` and inspect its JSON for these fidelity checks; do not mistake summary JSON for the complete project schema. Project format is versioned (this snapshot documents v17).

## Streams, linking and locks

**Multiple audio streams: yes; arbitrary multiple video stream selection: not established.**

- `MediaInfo` has `video: Option<VideoStreamInfo>` and `audio_streams: Vec<AudioStreamInfo>` (maximum placement count 64). `TrackItem.audio_stream` is a **zero-based index in the media audio-stream vector**, not necessarily the container's global packet/stream number. Default zero may be absent in serialized projects.
- `timeline.place {"item":ITEM,"track":"V1","audioTrack":"A1","seconds":0,"sourceIn":{"seconds":0},"duration":{"seconds":5},"video":true,"audio":true,"insert":false}` places picture and **all available audio streams** onto consecutive audio tracks, creating tracks as necessary. Stream-zero channel interpretation can produce additional audio clips; further streams retain their own channel layout. There is no `audioStream` or `videoStream` selector in this command's declared payload.
- `video:false` or an audio `track:"A2"` places sound only; `audio:false` places picture only. Choosing `"audioTrack":"A2"` chooses the destination, **not stream 2**. `clip.audioChannels` changes channel interpretation, not container video selection. Confirm the deployed catalog before relying on a stream-remapping setter; none was found in the inspected command registrations.
- Source therefore does **not** establish direct separation of OBS screen and camera stored as two video streams in one container. Separate source files or a separately approved preparation step would be needed unless runtime discovery proves otherwise. Do not silently pre-extract/transcode media.
- A placement's picture/audio clips share a `link`; multi-stream audio-only placement can also share one. `clip.link` toggles state rather than guaranteeing “link on”; inspect first. `sequence.linkedSelection {"on":true}` and `timeline.move {"moves":[{"clip":CLIP,"track":"V1","time":{"seconds":2}}],"linked":true}` carry linked partners by the same delta on their own tracks. Locked partners stay behind: **link is not a sync guarantee**.
- `timeline.setTrack {"track":"A1","locked":false,"syncLock":true,"enabled":true,"muted":false}`: `locked` prevents editing; `syncLock` includes a track in ripple operations; `muted`/`enabled` affect output, not synchronization. Use IDs after track insert/reorder, not permanent assumptions about A1/V1 names.
- `clip.synchronize {"clips":[C1,C2],"method":"audio","reference":C1,"offset":0}` also supports `in|out|timecode|marker`, `ignoreHours`, `marker`, and reference `track`. Offset is in **frames**. Audio alignment uses waveform cross-correlation, analyzes up to 30 minutes at 48 kHz, and the inspected analyzer reads the source's default audio, not a selectable arbitrary audio-stream argument. Synchronizing clips is distinct from linking them.

Evidence: `crates__media__src__lib.rs:170-225,257`; `crates__project__src__track.rs` (`audio_stream`, `source_channels` fields); `crates__engine__src__commands.rs:1178-1193,1231-1291,1468-1502,2490-2592,3315-3327,3618-3660`; `crates__engine__src__clip_ops.rs:167-174`; `docs__control-protocol.md:138-163`; `crates__engine__src__multicam.rs:141-146,363-468`; `crates__engine__src__sync.rs:1-29,140-168`.

## Time, coordinates, transforms, graphics and post-ripple timing

- Clock: **254,016,000,000 ticks/second**, signed integer tick storage. Source and sequence frame rates can differ. `timeline.place` uses source rate for `sourceIn` frame objects, sequence rate for duration/time; start and end snap independently to the sequence grid. Use integer ticks or rational-frame calculations, avoiding accumulated float seconds.
- At normal forward speed, source time is `sourceIn + (sequenceTime - clip.start)`. `source_time_at` handles speed/reverse/hold; `effect_time_at` keeps effects progressing during a frame hold. Clip effect keyframes live in **media time**; mixer track automation lives in **sequence time**.
- `effects.setParam {"clip":CLIP,"effect":"motion","param":"position","value":[1440,810]}` and `param:"scale",value:35` are static transform examples for a 1920×1080 sequence. Position is in sequence pixels; anchor is in source pixels; scale is **percent**, not 0–1. Defaults center the source anchor and place it at sequence center. Scaling-to-frame flags, pixel aspect ratio and source dimensions change the actual map; do not infer a final box from scale alone.
- Keyframing: `effects.setParam {"clip":CLIP,"effect":"motion","param":"position","value":[960,540],"time":254016000000,"keyframe":true}` supplies **sequence time** to the command, which converts to stored effect/media time. Explicit time outside the clip stays outside it; omitted time clamps the playhead to the clip. `effects.addKeyframe` **toggles**, so is not idempotent. `effects.deleteKeyframe` takes stored `mediaTime`, not the preceding sequence-time input. A static edit replying `keyframes:0` is success.
- Titles/highlight boxes: `graphics.newText {"text":"Key point","position":[100,100],"seconds":2,"track":"V2","time":TICKS}`; `graphics.newShape {"shape":"rectangle","position":[960,540],"size":[600,120],"seconds":2,"track":"V2","time":TICKS}`; then `graphics.set {"clip":GRAPHIC,"layer":LAYER,"props":{"fill":false,"stroke":true,"stroke_color":"#ffff00","stroke_width":6}}`. Discover returned IDs/layers with `graphics.list {"clip":GRAPHIC}`; do not copy illustrative placeholder IDs.
- Graphic positions are canvas pixels (shape position is its center; paragraph-text position is top-left). `graphics.list` exposes bounds/quads; UI screenshot/window points are a **different coordinate space**. “Highlight” here is an ordinary transparent graphic shape, not a verified semantic target-tracking API.
- Finish ripple/content cuts **before** scheduling overlays whenever possible. `edit.rippleDelete {"clips":[...]}` expands links and closes actually uncovered spans, merged across affected tracks, right-to-left. Other sync-locked unlocked tracks move only if their material does not conflict; a conflict fails the cloned edit. Locked tracks stay. Do not subtract the sum of all selected clip lengths (linked/overlapping clips double-count).
- For a surviving point outside deleted intervals, conceptual mapping is `newTime = oldTime - total closed duration before oldTime`; deleted points have no valid destination. Derive the **actual** map by comparing fresh sequence inspection/source ranges after each edit, not by trusting a planned cut list. Sequence markers move only when `markers.rippleSequenceMarkers {"on":true}`; caption tracks have separate lock/sync-lock state. Reinspect marker/caption/graphic timing and track automation after ripple.
- Media-time clip keys stay attached to media; trimming the head advances source-in and changes where those keys appear relative to clip start. Graphic responsive intro/outro retiming remaps **layer** keys, not the graphic clip's own Motion/Opacity/mask keys.

## Camera-only colour

Apply `effects.apply {"clips":[CAMERA_CLIP],"effect":"lumetri"}` and then `effects.setParam {"clip":CAMERA_CLIP,"effect":RETURNED_INDEX,"param":"exposure","value":0.2}`; use inspected camera clip IDs, not all selected picture. After cuts, find every camera-source instance and target those explicitly. Exposure's hard range here is −5…5; inspect the actual build's effect definitions before other adjustments.

Do **not** use a global adjustment layer/sequence colour setting for camera-only correction: those can affect screen/UI content. `clip.interpretFootage` is source-item interpretation and may affect every instance of that item; clip effects are the narrower seam. `lumetri.setInputLut`, `lumetri.setLook`, `lumetri.setSection` accept `clip`; optional targeting defaults must not choose the wrong visible clip. Colour match/LUT export are available but do not replace frame review.

Evidence: `crates__project__src__effect.rs:420-434`; `crates__engine__src__color.rs`; `docs__control-protocol.md:178-193`.

## Native audio DSP, mixing and delivery loudness

- Real native DSP code exists: EQ, compressor, gate, look-ahead limiter, dehum, denoise, de-esser, dereverb, speech-enhance, channel routing, etc. Its catalog is not proof of perceptual dialogue repair quality. No external neural model is required for the cited DSP.
- Clip seam: `effects.apply {"clips":[AUDIO_CLIP],"effect":"parametric_eq"}` → `effects.setParam` with the **engine-discovered** parameter IDs/ranges. Applying an audio effect to a picture clip expands to linked audio; for mic-only work target its audio clip explicitly, avoiding accidental treatment of desktop/system sound.
- Essential Sound commands accept explicit `clips`: `essentialSound.setType`, `essentialSound.set`, `essentialSound.autoMatch`, `essentialSound.generateDucking`. Automatch/ducking modify edits and need review; don't run implicitly on all sound.
- Mix seam: `mixer.inspect`, `mixer.setStrip {"strip":"A1","volumeDb":-3,"pan":0,"muted":false,"solo":false,"output":"Mix"}`; `mixer.addInsert {"strip":"A1","effect":"compressor"}` → `mixer.setInsert {"strip":"A1","slot":SLOT,"params":{...}}`; `mixer.setKeyframe {"strip":"A1","lane":"volume","time":TICKS,"value":-6}`; `mixer.writeAutomation {"strip":"A1","lane":"volume","points":[[T0,-6],[T1,0]]}`. Sends/submixes and pre/post-fader inserts are supported. Clip mixer records Volume/Panner keys in media time; track automation uses timeline ticks.
- `mixer.measure {"strip":"Mix",...}` is **not asserted** here: no such command was found. Native meter implementation exposes BS.1770-4/EBU R128 integrated/momentary/short-term/LRA/sample/true peak internally; inspect actual commands for a supported analysis endpoint.
- Delivery: `file.exportMedia` has flat `loudnessLufs`, or resolved settings `effects.loudness` with `enabled`, `targetLufs`, `truePeakDbtp`. Export measures the whole selected range, performs bounded gain refinement through a true-peak limiter, and compensates look-ahead delay. Impossible targets can plateau; the existence of normalization is not proof the delivered encoded audio meets target. Report records measured input LUFS and applied gain, not necessarily a complete achieved-output compliance report.

Evidence: `crates__audio-dsp__README.md:19-98` (oracle/test statements are **upstream claims**, not local results); `crates__audio-dsp__src__loudness.rs`; `crates__engine__src__mixer.rs:1-31,1239-1540`; `crates__engine__src__essential_sound.rs`; `crates__render__src__audio.rs`, `crates__render__src__mixer.rs`; `crates__export__src__audio_out.rs:19-140`.

## Export/interchange

Discover `export.formats`, `export.presets.list`, `export.presets.get`; dry-resolve with `export.resolve` before writing. Example command params: `{"path":"<approved-workspace>/smoke.mp4","format":"h264","range":"entire","audio":true,"wait":true,"hardwareEncoding":"off"}` for `file.exportMedia`. Use `range:"entire"` explicitly to avoid stale In/Out marks; custom uses `startSeconds`/`endSeconds`. Settings override preset; flat overrides apply too. Queue items snapshot the project at add time: edits afterward require requeueing.

Wait or follow returned `job` via `jobs.list`; queue list is not the direct-export job list. Verify completion/error, expected frame count/duration, warnings, encoder choice and **empty `offlineMedia`**. Placeholder/offline media may still yield a “successful” encode. Bridge preview is a Program-monitor screenshot; headless preview is rendered independently; neither alone proves full export parity.

`file.exportEdl`, `file.exportFcp7Xml`, `file.exportFcpxml`, `file.exportOtio`, `file.exportAaf`, `file.exportOmf` are registered in `commands.rs`; inspect each payload. Basic timeline interchange returns `{path,bytes,report}`; inspect `report`, not just command success. Keep `.fcproj` as native master: graphics/adjustment layers do **not** round-trip faithfully in any cited interchange; AAF/OMF lose unsupported picture/effects, OMF carries no video. Rendered audio effects/mixdowns can improve delivery but sacrifice editable structure.

**Dependency limit:** production FCP7/FCPXML/OTIO and AAF handling uses `craft-libs` components; some local parser modules are now test-only. Workspace pins `craft-timeline`/`craft-aaf` to `3b8e426a260695af840a2cd79a064d40778f939e` and `craft-audio` to `82062077bba679ba5236e2d1a391f02d1533cbab`. `Cargo.toml`/`Cargo.lock` and interchange facade were downloaded, but those dependency implementations were **not independently downloaded/audited**. Format fidelity statements above come from official docs/facade, not an exhaustive dependency proof or third-party-editor test.

## Minimal future smoke gate (not performed)

1. Record installed version/build and command/effect catalogs; compare with this pin. Open a scratch native project in an approved workspace, never overwrite source media or user's master. Import a known short camera file, screen file and mic/system-audio fixture with independently identifiable tones/content.
2. Place 5–10 seconds; verify item→clip/track IDs, source-in/out, rate, links, audio-stream vector order and saved per-clip stream/channel mapping. If input has two video streams, explicitly prove stream selection or stop as unsupported; do not assume “multitrack” covers it.
3. Move/trim linked A/V; verify same delta and source correspondence. Lock one partner to expose expected divergence, then undo. Test sync-lock on/off and a conflicting ripple: assert either all expected changes or no mutation. Verify undo restores timing/links.
4. Delete a known middle span; inspect actual closed duration and new IDs. Check source-frame continuity, audio alignment, marker/caption/overlay positions, track automation and keys at both sides of the cut. Use freshly mapped output times for all subsequent graphics.
5. Add two Motion keys, title and outline highlight. Inspect native stored key times plus frames before/during/after the animation and after a head trim. Verify source/canvas/window coordinate conversion, correct shape bounds, text legibility and no occlusion of meaningful screen content.
6. Apply camera-only grade and mic-only EQ/compression. Compare rendered frames showing camera **and** screen, ensuring screen pixels remain unchanged outside deliberate overlays. Listen across cuts; check channel routing, no doubled system/mic feed, limiter/DSP latency and no tail truncation.
7. Resolve then export the **entire** short sequence with audio/loudness settings. Require no missing media, correct frames/duration/rate/dimensions/channels and no unexpected warnings. Inspect encoded frames/video and listen; independently measure decoded output LUFS/true peak against the delivery specification (allow codec/tolerance policy, not blind exact equality).
8. Save/reopen native project and compare IDs/stream maps/keys/mix state. Export one intended interchange format, require/report all losses, reimport into scratch and compare source ranges/links/timing. Do not demand graphic fidelity where upstream explicitly warns of loss.

**Decision:** credible source-level agent primitives exist for a separate-file camera/screen/mic workflow. Main blockers to assuming drop-in parity are multi-video-stream selection, incomplete inspection schema, post-ripple retiming/identity, untested DSP/render/export behavior, and lossy interchange. All remain runtime acceptance work, not completed validation.
